# 后端插件开发

本仓库除浏览器端的前端界面/脚本外, 还支持开发 **后端插件** (SillyTavern 服务端插件, Server
Plugin), 用于实现浏览器无法完成的能力, 例如持有密钥调用外部 API、注册 HTTP 端点供前端调用。

## 目录约定

- 插件源码: `src/plugins/<插件名>/index.ts`, 每个子目录一个插件
- 编译产物: `dist/plugins/<插件名>/index.cjs`, **随仓库提交** (与 `dist/` 相同), 但**不会**被 CI 上传到 CDN/R2 (R2 同步
  `dist/` 时会明确排除 `dist/plugins/`)
- **每个插件占一个文件夹** (目录插件形态), 多插件共存互不干扰; 部署时把整个 `dist/plugins/<插件名>/`
  文件夹复制到 SillyTavern 的 `plugins/` 目录
- 插件类型定义: `src/plugins/@types/sillytavern-plugin.d.ts` (最小化的 `info`/`init`/`exit` 与路由类型)
- 类型检查配置: `tsconfig.plugins.json` (Node 环境), 检查命令 `npx tsc --noEmit -p tsconfig.plugins.json`

## 构建

```bash
pnpm build:plugins          # 生产构建 (minify), 输出 dist/plugins/<插件名>/index.cjs
pnpm build:dev -- --kind=plugins # 开发构建 (不压缩)
pnpm watch:plugins          # 监听 src/plugins 自动重建
```

统一构建脚本 `tools/build.ts` 使用 tsdown:

- 目标 `node18`, 产物为 CommonJS 单文件, 第三方依赖 (如 `nekoai-js`) 全部打进产物, 运行时不依赖 node_modules
- 仅外部化 Node 内置模块与 `canvas` (nekoai-js 的可选依赖, 其内部有 catch 兜底)
- 插件内可直接读取 `process.env` (产物不做 define 替换), 因此可读环境变量如 `NOVELAI_TOKEN`
- 插件依赖通过 `pnpm add -D <包>` 安装即可 (打进产物, 无需放进运行时依赖)

## 插件形态 (SillyTavern Server Plugin)

SillyTavern 服务端插件的加载约定 (见 SillyTavern `src/plugin-loader.js`):

- 插件文件放在 SillyTavern 根目录的 `plugins/` 文件夹, 需在 `config.yaml` 开启 `enableServerPlugins: true`
- 每个插件以独立文件夹存在 (目录插件), loader 对目录按 `index.js` -> `index.cjs` -> `index.mjs` 的顺序查找入口
- 模块导出 `info` (含 `id`/`name`/`description` 字符串, `id` 只能是小写字母、数字、`-`、`_`) 和 `init(router)`, 可选
  `exit()`
- `init` 收到的 router 是 SillyTavern 创建的 Express Router, 注册的路由挂载在 `/api/plugins/{id}/` 下
- **产物必须用 `.cjs` 扩展名**: SillyTavern 根目录 `package.json` 是 `"type": "module"`, 若用 `.js`
  会被当作 ESM 解析导致 CJS 产物报错; `.cjs` 始终按 CommonJS 解析, 动态 `import()` 后 loader 通过 `plugin.default?.init`
  兼容
- 插件端点位于酒馆鉴权中间件之后, 前端调用必须携带 `SillyTavern.getRequestHeaders()`
- 插件代码在 Node 进程内运行, 可使用 Node 内置模块与 `process.env`; 未沙箱化, 只安装可信来源的插件

## 前端如何调用

```typescript
const response = await fetch('/api/plugins/nekoai/probe', {
  method: 'GET',
  headers: SillyTavern.getRequestHeaders(),
});
```

`src/scripts/ImgGenHelper/adapters/ai/plugin-backend-probe.ts`
提供了现成的探测封装 (带 3 秒超时、结果缓存), 可作为前端探测后端插件的参考。

## 现有插件

### llm-requester (OpenAI-compatible LLM Requester)

基于 Vercel AI SDK 的独立非流式 LLM 请求器。插件 ID 为 `llm-requester`，公开自有的严格请求协议，不复用酒馆
`/api/backends/chat-completions/generate` 的平铺请求体，也不兼容 Tavern Helper 的 `generateRaw` 或代理预设。

- `GET /api/plugins/llm-requester/v1/capabilities`: 查询运行时兼容性、Provider 注册表及当前用户的凭证 ID/标签。
- `POST /api/plugins/llm-requester/v1/models`: 按 Provider、凭证 ID 和可选 Custom Base URL 获取模型列表。
- `POST /api/plugins/llm-requester/v1/generate`: 按所选连接执行 OpenAI-compatible 文本或工具调用生成。
- 每个 Provider 映射到对应的 SillyTavern 密钥类型；插件通过 `SecretManager.readSecret(key, id)`
  在服务端读取指定凭证，前端不会获得密钥值。Custom 支持多个已保存凭证，也允许无密钥请求。
- 固定 Provider 的 Base URL 由插件注册表决定，只有 Custom 接受调用方传入的 HTTP(S) Base URL。
- 模型发现使用 OpenAI Node SDK，生成使用 Vercel AI SDK；不要在调用脚本中自行请求上游 `/models` 或 chat completions。
- 请求消息允许以 `assistant` 结尾，以支持兼容服务的 assistant prefill。
- 服务端只返回 tool call，不执行工具；调用脚本负责后续动作。

插件加载器目前只向插件传入 Express Router，不提供 secrets 或配置依赖。`llm-requester` 因此将对
`src/endpoints/secrets.js`、`src/constants.js` 和 `src/additional-headers.js`
的动态导入集中在独立运行时 adapter 中。不要让其他领域代码直接依赖这些 SillyTavern 内部模块；内部接口不兼容时应保留 capabilities 端点并返回明确错误。

共享请求 schema 和浏览器客户端位于 `util/llm-requester/`。

### imggen-novelai (NovelAI Structured Backend)

面向新生图脚本的严格 NovelAI text2image 后端，只支持 V4.5 / V5，不兼容酒馆旧生图请求布局，也不依赖
`ImgGenHelper`。插件 ID 为 `imggen-novelai`，Token 只从服务端环境变量 `NOVELAI_TOKEN` 读取。

#### 端点

| 方法 | 路径                                          | 说明                                    |
| ---- | --------------------------------------------- | --------------------------------------- |
| GET  | `/api/plugins/imggen-novelai/v2/capabilities` | 返回模型、限制、输出模式及 Token 配置状态 |
| POST | `/api/plugins/imggen-novelai/v2/generate`     | 结构化 V4.5/V5 text2image，存储图片或返回单张原图 |

生成端点接收严格 JSON：

```json
{
  "operationId": "11111111-1111-4111-8111-111111111111",
  "model": "nai-diffusion-5-full",
  "prompt": "2girls, café",
  "uc": "lowres, bad anatomy",
  "characters": [
    {
      "prompt": "girl, red hair",
      "uc": "blue hair",
      "position": { "x": 0.25, "y": 0.5 }
    }
  ],
  "size": { "width": 1216, "height": 832 },
  "sampling": {
    "steps": 23,
    "scale": 7,
    "sampler": "k_euler_ancestral",
    "schedule": "karras",
    "seed": null
  },
  "output": {
    "mode": "stored",
    "storage": { "characterName": "Alice", "filename": "novelai_example" }
  }
}
```

- `prompt` / `uc` 是最终文本，插件不会追加质量词、UC preset，也不会解析 `|`。
- `characters` 是角色正向、负向和位置的唯一数据源；插件负责投影为 NovelAI wire 的三组角色字段。
- 未知字段会返回 `400 VALIDATION_ERROR`；旧字段不会被静默忽略。
- V4.5 最多 6 个角色，手动坐标限 5×5 网格；V5 最多 22 个角色，坐标范围为 `[0, 1]`。
- v2 固定一次生成一张图，`output.mode` 必须显式选择 `stored` 或 `binary`。
- `stored` 直接写入 `req.user.directories.userImages`，目录、文件名、扩展名和返回路径遵循 SillyTavern `/api/images/upload` 的原生规则，响应为包含 `path`、`mime`、`bytes`、seed 和 model 的 JSON。
- `binary` 不落盘，以图片二进制返回；实际 seed 位于 `X-Imggen-Seed` 响应头。
- `operationId` 在当前服务进程内提供短期幂等：同一用户的相同请求会复用结果，不同请求复用同一 ID 返回 409。
- 插件不会联动删除已经保存的图片；孤儿文件仍交由用户或 SillyTavern Data Maid 处理。
- 错误响应统一为 `{ error: { code, message, issues? }, requestId }`。

部署方式与其他目录插件相同：复制 `dist/plugins/imggen-novelai/` 到 SillyTavern `plugins/`，启用服务端插件并设置
`NOVELAI_TOKEN`。

### nekoai (NekoAI Bridge)

基于 [NekoAI-JS](https://github.com/Nya-Foundation/NekoAI-JS) 将 NovelAI text2image 封装为后端端点, 供前端脚本调用。

#### 端点

| 方法 | 路径                           | 说明                                                                                   |
| ---- | ------------------------------ | -------------------------------------------------------------------------------------- |
| GET  | `/api/plugins/nekoai/probe`    | 探测插件是否可用, 返回 `{ ok: true, plugin: 'nekoai', version: '1.0.0' }` (无需 token) |
| POST | `/api/plugins/nekoai/generate` | text2image 生成                                                                        |

#### 请求体 (POST /generate)

| 字段               | 类型    | 必填 | 说明                                                                                                                                                       |
| ------------------ | ------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`           | string  | 是   | 正向提示词                                                                                                                                                 |
| `token`            | string  | 否   | NovelAI token, 覆盖环境变量 `NOVELAI_TOKEN`                                                                                                                |
| `negative_prompt`  | string  | 否   | 负面提示词                                                                                                                                                 |
| `model`            | string  | 否   | 如 `nai-diffusion-4-5-curated`, 默认由 API 决定                                                                                                            |
| `sampler`          | string  | 否   | 与酒馆兼容: `k_euler_ancestral` / `k_euler` / `k_dpmpp_2m` / `k_dpmpp_sde` / `k_dpmpp_2s_ancestral` / `ddim` (自动映射 `ddim_v3`); 不支持的 sampler 被忽略 |
| `scheduler`        | string  | 否   | `karras` / `native` / `exponential` / `polyexponential` (映射到 `noise_schedule`)                                                                          |
| `steps`            | number  | 否   | 1-50                                                                                                                                                       |
| `scale`            | number  | 否   | guidance scale                                                                                                                                             |
| `width` / `height` | number  | 否   | 输出尺寸                                                                                                                                                   |
| `seed`             | number  | 否   | 随机种子, `< 0` 视为随机                                                                                                                                   |
| `n_samples`        | number  | 否   | 生成数量, 1-8                                                                                                                                              |
| `sm` / `sm_dyn`    | boolean | 否   | SMEA 开关                                                                                                                                                  |

#### 响应

```json
{
  "images": [{ "data": "<base64 png>", "mime": "image/png" }]
}
```

错误时返回非 2xx 状态码 + `{ "error": "<消息>" }`; NovelAI API 错误状态码会透传 (如 402 Anlas 不足)。

#### 部署

1. 构建: `pnpm build:plugins`
2. 将 `dist/plugins/nekoai/` 整个文件夹 (含 `index.cjs`) 复制到 SillyTavern 的 `plugins/` 目录, 即最终路径为
   `plugins/nekoai/index.cjs`
3. `config.yaml` 设置 `enableServerPlugins: true`
4. 为 SillyTavern 进程设置环境变量 `NOVELAI_TOKEN` (NovelAI persistent token)

#### 许可证

`nekoai-js` 采用 AGPL-3.0。本仓库为公开仓库, 插件源码随仓库分发即可满足合规要求; 引入新的插件依赖时注意检查许可证。

### novelai (NovelAI Bridge Thin)

基于 [novelai-bridge](https://github.com/RhNu/novelai-bridge) (Apache-2.0) wire 协议的轻量 NovelAI text2image 后端端点,
**不依赖 nekoai-js**, 仅支持 V4.5 / V5 模型。

#### 端点

| 方法 | 路径                            | 说明                                                                                    |
| ---- | ------------------------------- | --------------------------------------------------------------------------------------- |
| GET  | `/api/plugins/novelai/probe`    | 探测插件是否可用, 返回 `{ ok: true, plugin: 'novelai', version: '1.0.0' }` (无需 token) |
| POST | `/api/plugins/novelai/generate` | text2image 生成                                                                         |

#### 请求体 (POST /generate)

与 nekoai 的请求体字段兼容, 仅模型白名单与部分参数行为不同:

| 字段               | 类型    | 必填 | 说明                                                                                                                                     |
| ------------------ | ------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`           | string  | 是   | 正向提示词                                                                                                                               |
| `token`            | string  | 否   | NovelAI token, 覆盖环境变量 `NOVELAI_TOKEN`                                                                                              |
| `negative_prompt`  | string  | 否   | 负面提示词, 为空时使用 Light ucPreset 文本                                                                                               |
| `model`            | string  | 否   | **仅支持** `nai-diffusion-4-5-full` / `nai-diffusion-4-5-curated` / `nai-diffusion-5-full` / `nai-diffusion-5-curated`, 其他模型返回 400 |
| `sampler`          | string  | 否   | 与 nekoai 取值一致, 但 `k_dpm_fast` 被忽略 (V4.5/V5 下不存在)                                                                            |
| `scheduler`        | string  | 否   | `native` 会被强制映射为 `karras` (V4+ 不接受 native)                                                                                     |
| `steps`            | number  | 否   | 1-50                                                                                                                                     |
| `scale`            | number  | 否   | guidance scale                                                                                                                           |
| `width` / `height` | number  | 否   | 输出尺寸                                                                                                                                 |
| `seed`             | number  | 否   | 随机种子, `< 0` 或 `0` 视为随机                                                                                                          |
| `n_samples`        | number  | 否   | 生成数量, 1-4                                                                                                                            |
| `sm` / `sm_dyn`    | boolean | 否   | **忽略** (V4.5/V5 均不支持 SMEA)                                                                                                         |
| `decrisper`        | boolean | 否   | **忽略** (V4.5/V5 均不支持 dynamic thresholding)                                                                                         |
| `variety_boost`    | boolean | 否   | 仅 V4.5 生效 (映射为 `skip_cfg_above_sigma`); V5 忽略                                                                                    |
| `upscale_ratio`    | number  | 否   | **忽略** (novelai-bridge 未封装该参数)                                                                                                   |

#### 请求协议 (wire)

- 端点 `https://image.novelai.net/ai/generate-image`, 请求头 `Authorization: Bearer <token>` +
  `Content-Type: application/json`
- V4+ 使用 `v4_prompt` / `v4_negative_prompt` 结构 (顶层 `prompt` / `uc` 省略); V5 额外发送
  `params_version: 4`、`legacy_uc: false`、`tag_hint_transparent_background: false`, V4.5 为 `params_version: 3`
- 质量标签 `, very aesthetic, masterpiece, no text` 追加到 `v4_prompt.caption.base_caption`
- 固定字段:
  `ucPreset: 1`、`qualityToggle: true`、`cfg_rescale: 0`、`characterPrompts: []`、`legacy: false`、`legacy_v3_extend: false`、`deliberate_euler_ancestral_bug: false`、`prefer_brownian: true`、`auto_smea: false`、`add_original_image: true`、`inpaintImg2ImgStrength: 1`、`use_coords: false`
- 超时 120 秒; 失败时透传 NovelAI API 的 HTTP 状态码与错误信息

#### 响应

与 nekoai 相同:
`{ "images": [{ "data": "<base64>", "mime": "image/png" }] }`。原始响应为 ZIP 容器 (多图) 或裸字节 (单图), 按 ZIP
entry 扩展名 / magic bytes (PNG `89504E47`、JPEG `FFD8FF`、WebP `RIFF..WEBP`) 解析。

#### 部署

与 nekoai 相同: 构建后复制 `dist/plugins/novelai/` 整个文件夹到 SillyTavern `plugins/` 目录, 并设置环境变量
`NOVELAI_TOKEN`。

#### 许可证

运行时无第三方 JS 依赖 (构建产物内嵌 `fflate`, MIT); 请求协议参考 novelai-bridge (Apache-2.0)。
