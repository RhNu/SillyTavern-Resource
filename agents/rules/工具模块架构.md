# 工具模块架构

`util` 的顶层按依赖环境和职责分区，功能内部按实际复杂度拆文件。单个文件能表达的职责不创建同名目录；
只有需要共同维护多个实现、适配器或资源的功能才建目录，测试跟随实现。

## 模块边界

| 目录 | 职责 | 依赖方向 |
| --- | --- | --- |
| `core` | 集合、日志、序列化、校验、标识符 | 仅基础库，不调用酒馆 API 或 UI |
| `st` | 宿主 DOM 上下文、原生命令注册 | SillyTavern 原生能力，不依赖 UI 或酒馆助手工具 |
| `tavern-helper/script` | 脚本实例的宿主节点、样式、生命周期、说明和版本提示 | 酒馆助手脚本接口 |
| `tavern-helper/state` | 变量读写、脚本配置同步、MVU 状态存储 | 酒馆助手变量接口、状态库，不依赖 UI |
| `ui` | 按用户交互功能组织的共享 UI | 可组合 `core`、`st`、`tavern-helper`，不依赖业务脚本 |
| `llm-requester` | 服务端插件与浏览器共享的协议，以及浏览器客户端 | 协议不依赖客户端或浏览器宿主 |

酒馆助手特有但尚不构成子系统的能力直接使用具体文件名，例如 `tavern-helper/regex.ts`。
宿主无关的工具仍可能使用构建配置提供的第三方库全局变量；这里的边界指不依赖酒馆运行时。

## 功能聚类

- 弹窗：`ui/popup` 包含原生适配、builder、快捷入口、React 挂载和帮助标记。
- 扩展设置：`ui/extension-settings` 包含宿主挂载、React 适配和设置抽屉。
- 悬浮窗：`ui/floating/position.ts` 仅处理尺寸与坐标；`surface.ts` 负责 DOM 测量、拖拽和会话生命周期。
- 流式消息：`ui/streaming-messages/context.ts` 提供 React provider 与 hook；`mount.ts` 负责酒馆事件和消息节点挂载。
- 状态：`tavern-helper/state/variables.ts` 提供变量访问；`script-settings.ts` 管理校验、迁移和延迟保存；
  `mvu-store.ts` 管理 MVU 的双向同步，避免把状态库归入展示层。

原生实现不反向导入 React 适配。调用方直接导入具体职责文件，功能内部使用相对路径；不为旧路径维护转发模块，
也不增加聚合所有 UI 的入口，以免普通组件导入时连带引入宿主挂载代码。

## API 命名

名称应直接表达行为，如 `mergeReplacingArrays`、`parseStructuredText`、`stringifyLiteralYaml`。
React 消费流式上下文统一使用 `useStreamingMessageContext`，不保留 `inject` 同义入口。
重构时同步更新调用方、示例、模板、测试和规则文档；构建产物由生产构建生成。
